# AGENTS.md — правила для всех агентов

Единственный источник правил. `CLAUDE.md` импортирует этот файл.

## 1. Что читать (экономия контекста)

1. Этот файл (загружается автоматически).
2. `PLAN.md` — найти задачу.
3. Только то, что указано в строке **Читать** задачи, и файлы, которые меняются.

`CONTEXT.md` и `docs/DECISIONS.md` целиком — только если задача ссылается на раздел, которого нет в «Читать», или при первой сессии. Все решения приняты: не предлагать альтернатив, не пересматривать ADR.

## 2. Роли

| Роль | Кто | Отвечает за |
|---|---|---|
| Исполнитель | Claude Code, Sonnet 4.6 | Одна задача `AGENT` за сессию |
| Ревьюер | Отдельная модель | Задачи с `[R]` и общее ревью в конце этапа, по `docs/REVIEW.md` |
| Координатор | ChatGPT / независимый GPT-ревьюер | Проверка `[R]`, этапов, статуса PLAN; эскалации по docs/COORDINATOR.md |
| Человек | Владелец | Секреты, `make spike`, `make invite`, утверждение ADR, merge, deploy |

## 3. Цикл задачи

1. Первая незакрытая задача `AGENT` в PLAN.md с закрытыми зависимостями.
2. Ветка `t-XXX-имя`.
3. План в чат в 3–5 строк: файлы, тесты, «Готово». Подтверждения не ждать.
4. Тесты → код → `make check` зелёный.
5. Чекбокс в PLAN.md; при изменении API — API_MATRIX.
6. Коммит `T-XXX: <что сделано>`, отчёт по шаблону (раздел 7).
7. `[R]` — передать ревьюеру; без `[R]` — сразу следующая задача. Не мержить.

Diff больше ~400 строк — разбить задачу на `T-XXXa/b` в PLAN.md.

**Текущий запуск:** диспетчера и Runner ещё нет. Владелец запускает `claude` вручную. Автоматизация (`T-106`–`T-108`) появится отдельными задачами. До её приёмки нельзя объявлять задачи запущенными, проверенными или завершёнными автоматически. Отдельные агенты работают в отдельных ветках и рабочих деревьях. ChatGPT может готовить заготовки кода по поручению владельца; интеграция только после проверок и одобрения владельца (ADR-22).

## 4. Когда спросить человека

Только: нужен запуск с реальными токенами; новая зависимость сверх раздела 2 PLAN.md; изменение ADR; критерий «Готово» противоречит документам. Формат: что мешает, варианты, рекомендация.

Операция YCLIENTS `unavailable` — применить fallback из API_MATRIX и продолжить без вопросов.

## 5. Запреты

- В YCLIENTS — только операции `kind: read` из API_MATRIX.
- Не читать и не выводить секреты; не запускать `printenv`, `env`, `docker compose config`, `docker inspect`; не читать файлы вне репозитория.
- Не выдумывать пути и поля: только API_MATRIX и fixtures.
- Не хранить имена и телефоны из YCLIENTS (ADR-06); не логировать payload; внешнее — через `redact()`.
- Числа — только `studio.yaml`, тексты — только `app/texts/ru.py`.
- Не ослаблять тесты и проверки.
- Не делать `git push`, `git merge`, `git reset --hard`.

## 6. Код

- Логика — чистые функции в `app/domain/`, табличные тесты (`pytest.mark.parametrize`), время — параметром.
- Побочные эффекты — UNIQUE `dedupe_key`; Telegram — только через outbox.
- Handlers тонкие: разбор ввода → сервис → ответ. Тестируются сервисы.
- `can()` вызывается в сервисе для каждого действия.
- UTC в БД, `Europe/Moscow` в логике.
- Минимум зависимостей: только стек из PLAN.md, раздел 2.

**Команды:** `make setup` (uv sync), `make check` (ruff format --check, ruff check, pyright, pytest), `make test`, `make run`, `make migrate`, `make health`. Только человек: `make spike`, `make invite`.

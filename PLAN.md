# PLAN — Telegram-бот студии «Мастерская»

> Версия: 2.3 · Дата: 2026-11-12 · Статус: **T-101 реализована, ожидает проверки координатором**
> Единственное место статуса задач. Все решения приняты (docs/DECISIONS.md); задачи выполняются по зависимостям без ожидания ответов, кроме HUMAN/эскалаций.
>
> **Оркестрация агентов вне репозитория.** Runner, GPT-ревью и диспетчер относятся к общей системе управления разработкой, не к продукту «Мастерская». Пока внешняя система отсутствует, Claude Code запускается вручную. Текущий план содержит только задачи Telegram-бота.

## 1. Что строим

Один Telegram-бот, который только читает YCLIENTS:

- **Администратор:** уведомления о записях и отменах, утренняя сводка, очередь задач, ответы пользователям через бота.
- **Клиент:** привязка по номеру, расписание и ссылка на онлайн-запись, свои записи, напоминание с «Приду / Не смогу», вопрос администратору, оценка занятия.
- **Преподаватель:** свои занятия и аренды, уведомления, свободные окна с запросом брони, подборка окон.
- **Рассылки:** анонсы подписавшимся и служебные сообщения участникам занятия.
- **Владелец:** еженедельный отчёт о стабильно пустых окнах аренды.

**Не строим:** запись и отмену через API, абонементы, явку, отчёт по аренде, платежи, webhook, веб-сервер, хранение клиентской базы, Runner, GPT-ревьюер, диспетчер.

## 2. Архитектура

```text
           python -m app  (один процесс, asyncio)
 ┌───────────────────────────────────────────────────────────┐
 │ bot polling (aiogram 3) ── services ── RBAC               │
 │ sync каждые 5 мин ── YCLIENTS (read) ── diff() ── events  │
 │ rules() ── tasks / outbox      scheduler ── напоминания,  │
 │ outbox sender ── Telegram       сводки, окна, рассылки    │
 └──────────────────────────── SQLite (data/bot.db, WAL) ────┘
```

**Детерминированное ядро — чистые функции `app/domain/`** (табличные тесты, без IO):

| Функция | Вход → выход |
|---|---|
| `diff(prev, cur)` | Снимки записей → события |
| `rules(event, cfg)` | Событие → задачи и сообщения |
| `occupancy(records, activities, halls)` | Данные YCLIENTS → занятые слоты |
| `empty_windows(weeks, cfg)` | 8 недель занятости → окна с упущенной выручкой |
| `free_slots(occupancy, days)` | Занятость → свободные слоты |
| `price(hall, dt)` | Цена часа |
| `match_phone(phone, candidates)` | Номер → клиент / штатный / арендатор / неоднозначно |
| `segment(users, name)` | Сегмент → `telegram_user_id[]` |
| `can(user, action, target)` | RBAC |

**Стек:** Python 3.12, uv, aiogram 3, httpx, SQLAlchemy 2 + aiosqlite, Alembic, pydantic-settings, PyYAML. Проверки: ruff, pyright, pytest, respx. Docker — только для VPS.

## 4. Модель данных (SQLite)

| Таблица | Поля и инварианты |
|---|---|
| `users` | `telegram_user_id` PK, `tg_username`, `tg_first_name`, `role`, `is_owner`, `teacher_kind`, `yclients_client_id`, `yclients_staff_id`, `consent_at`, `news_opt_in`, `slot_digest_enabled`, `source`, `blocked_at`, `created_at` |
| `invites` | `token_hash` UNIQUE, `role`, `created_by`, `expires_at`, `used_by`, `used_at` |
| `record_snapshots` | PK `record_id`; `staff_id`, `client_id`, `activity_id`, `service_id`, `hall_code`, `starts_at`, `ends_at`, `deleted`, `content_hash`, `seen_at` |
| `events` | `type`, `record_id`, `payload_min`, `created_at`, `dedupe_key` UNIQUE |
| `tasks` | `code`, `title`, `body`, `ref`, `requester_id`, `state` (`open`/`taken`/`done`), `taken_by`, `taken_at`, `done_at`, `due_at`, `last_ping_at`, `dedupe_key` UNIQUE |
| `outbox` | `telegram_user_id`, `kind`, `payload_min`, `state`, `attempts`, `next_attempt_at`, `dedupe_key` UNIQUE |
| `broadcasts` | `id`, `kind`, `segment`, `record_ref`, `text`, `photo_file_id`, `created_by`, `state`, `sent`, `failed`, `blocked`, `unsubscribed` |
| `answers` | PK (`record_id`, `telegram_user_id`, `kind`); `kind` = `rsvp`/`feedback`, `value`, `answered_at` |
| `kv` | `key` PK, `value` — heartbeat, время последней синхронизации, `scheduled:<job>:<period>` от двойного запуска |
| `audit_log` | `actor`, `action`, `target`, `created_at` |

## 5. Инварианты

1. Повторный прогон синхронизации на тех же данных → ноль новых событий, задач, сообщений.
2. Каждый побочный эффект защищён UNIQUE (`dedupe_key` или PK).
3. Telegram — только через outbox: backoff при 429 и сбоях; блокировка бота → `blocked_at`.
4. Право проверяется в сервисе для каждого действия и каждой кнопки.
5. Тихие часы применяются при постановке в outbox.
6. Тесты без сети и реального времени. Handlers тонкие; тестируются сервисы.

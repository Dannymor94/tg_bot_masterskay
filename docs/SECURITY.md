# SECURITY — секреты и персональные данные

**Никогда не коммитить** `secrets.env`, `.env`, токены, реальные YCLIENTS/Telegram payload, базы SQLite, пользовательские номера телефонов и сырые fixtures.

- Источник секретов — `~/.config/studio-bot/secrets.env`, права `600`; в Git только `config/env.example` с пустыми значениями.
- Не переносить значения секретов в запросы моделей, README, Markdown-отчёты, issue, PR, CI-логи, скриншоты или тесты.
- Если секрет уже появился в чате/коммите: считать его раскрытым, рекомендовать перевыпуск и устранение из истории по согласованию с владельцем.
- Агентам запрещено читать файлы с секретами и запускать команды для просмотра окружения. Настройки Claude Code — дополнительный, не единственный рубеж.
- YCLIENTS в обычном боте: только `kind: read` и `verified`; реальный spike — только человек. До подтверждения операции не использовать кандидатов как реальные endpoints.
- Персональные данные YCLIENTS не сохранять, кроме оговорённого ADR-06 случая открытой R4; логи содержат только идентификаторы.
- Результат ревью можно отправлять во внешний OpenAI API только после отдельной проверки diff/fixtures на секреты и персональные данные. При сомнении — остановка.
- Секреты и `data/` исключены через .gitignore, но **.gitignore не защищает уже отслеживаемые файлы**; нужен preflight перед commit/push.

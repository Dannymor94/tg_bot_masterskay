# Нативный интерфейс Telegram «Мастерская»

`/menu` открывает интерактивное Rich Message с оформлением и разделами, доступными по фактической роли Telegram ID. Кнопки имеют серверную авторизацию. Для отдельных разделов (`role-screen.png`) используются собственные иллюстрации. Ни Mini App, ни туннель Cloudflare для этих экранов не нужны.

## Клиент: календарь и запись

1. **Расписание** → месяц → день (в пределах ближайших 90 дней).
2. Дата **не означает наличие свободных мест**: `records.list` в YCLIENTS возвращает 403, поэтому подтвердить доступность невозможно.
3. **Запросить запись на эту дату** → ответить боту текстом о практике/желательном времени → создаётся задача R3 администратору.
4. В **Мои записи** до восстановления YCLIENTS видны только собственные заявки к администратору, а **не подтверждённые CRM-записи**.
5. Администратор проверяет доступность самостоятельно и согласовывает её с человеком. Прямого бронирования, отмены и списания абонемента бот сейчас не выполняет.

Для преподавателя **Аренда** использует такой же выбор даты и создаёт задачу R1 для администрации. Свободные окна также не могут отображаться до подтверждённого источника.

## Владелец: что значат отчёты

В меню **Отчёты** переключаются разделы **Обзор / Задачи / Рассылки / Люди**. Каждый переход заново читает SQLite бота.

| Показатель | Что считается | Источник |
| --- | --- | --- |
| Ожидают исполнителя | Задачи в состоянии `open` | `tasks` |
| В работе | Задачи в состоянии `taken` | `tasks` |
| Выполнены за всё время | Задачи в состоянии `done` | `tasks` |
| По направлениям R1–R8 | Активные и закрытые задачи каждого правила | `tasks.code`, `tasks.state` |
| Черновики / отправляются / завершены | Рассылки бота по состояниям | `broadcasts` |
| Доставлено / ошибки | Накопленные счётчики рассылок бота | `broadcasts.sent`, `.failed` |
| Администраторы / преподаватели / клиенты | Неотозванные Telegram ID, которые не заблокировали бота | `users.role` |
| Подписчики новостей | Активные Telegram ID с согласованной подпиской | `users.news_opt_in` |

Это **операционные показатели бота**. Они не показывают выручку, долю занятости залов, продажи абонементов, доход преподавателей, настоящие свободные окна или посещения YCLIENTS. Нули означают отсутствие записей в **локальной** базе, а не отсутствие событий в студии.

## Тестовый проход в Telegram

Обновить `main` и запустить бота локально через `make run`, затем `/menu`. Проверить визуальный переход с разными картинками. Клиенту/преподавателю для входа нужна уже подтверждённая роль/привязка. Не подтверждать реальные рассылки и не отзывать чужой доступ во время визуального теста. Синтетические тесты и GitHub CI не заменяют проверку фактического Telegram-клиента.

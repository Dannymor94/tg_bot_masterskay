# ARCHITECTURE — целевая архитектура MVP

**Статус:** проектный контракт, не доказательство реализации. Не заменяет ADR из `DECISIONS.md`.

## Топология

```text
Telegram (polling, aiogram 3) --> handlers --> services --> domain (pure)
                                            |        |
YCLIENTS (read-only, polling 5m) --> adapter --+        +--> rules/diff/occupancy
                                            |
                                            +--> SQLite (WAL, SQLAlchemy, Alembic)
                                            +--> durable outbox --> Telegram sender
Scheduler ---------------------------------+
```

Один процесс `python -m app` и один asyncio-цикл. Docker Compose на VPS с одним сервисом. Webhook, Redis, PostgreSQL и операции записи в YCLIENTS отсутствуют в MVP.

## Направление зависимостей

- `app/domain/` — только чистые функции и детерминированные типы; не импортирует сеть, БД или Telegram.
- `app/integrations/` — нормализация только `verified, kind: read` операций `API_MATRIX.yaml`. `pending` разрешён только spike с явным флагом владельца.
- `app/services/` — сценарии, RBAC при каждом действии, транзакции и побочные эффекты через outbox.
- `app/jobs/` — polling/sync/scheduler/outbox, обработка рестартов, блокировок и повторов.
- `app/bot/` — тонкие handlers, форматирование ответов через `app/texts/ru.py`.
- `app/db/` — таблицы и миграции из `PLAN.md §4`.

## Ключевые гарантии

1. Идемпотентный `diff` и уникальные `dedupe_key` для событий, задач, уведомлений.
2. Повторная обработка одного события не порождает новое сообщение.
3. Атомарное взятие задачи через условное обновление.
4. Бизнес-время `Europe/Moscow`, хранение timestamp в UTC.
5. Занятость зала = брони на колонке зала + групповые события с ресурсом зала.
6. Данные YCLIENTS не копируются в отдельную клиентскую базу.
7. Реальные поля API не придумываются: только матрица и проверенные fixtures.

## Модульная интеграция

Стек и таблицы утверждаются T-101. T-102 и T-105 могут разрабатываться параллельно после T-101 только с непересекающимися файлами. Изменения общего интерфейса — отдельная задача/ревью. См. `CONTRACTS.md`.

# SPIKE_RUNBOOK — живой read-only spike YCLIENTS (T-103b)

**Запускает только владелец и только после независимого QA кода.** Агент spike не запускает, реальные секреты не читает, API не вызывает. Spike не помечает операции `verified` и не меняет `docs/API_MATRIX.yaml` — он лишь предлагает патч для отдельного одобрения.

## Что делает spike

- Перебирает статические кандидаты `kind: read` из `API_MATRIX.yaml` (только из code-review allowlist `SAFE_READ_ROUTES`).
- По одному запросу на кандидата, с таймаутом, повторами, бюджетом запросов из `studio.yaml → yclients_http`. Каждый путь содержит `company_id` — привязка к филиалу.
- Печатает только: id операции, метод кандидата, HTTP-статус / категорию ошибки. Ни тела ответа, ни значений полей, ни секретов, ни заголовков.
- На первый успех пишет **обезличенную схему** (shape-only, без значений) в `tests/fixtures/yclients/<op>.json`.
- `record.get` не пробуется (нужен реальный record_id из подтверждённого `records.list`). `clients.search_by_phone` не пробуется без приватного тестового телефона.

HTTP 200 сам по себе не делает операцию `verified`. Промоушен в `verified` и правку `API_MATRIX.yaml` / `studio.yaml` владелец выполняет вручную **только после** независимой проверки обезличенных fixtures и предложенного патча.

## Предусловия

- Пройден независимый QA этого кода на точном SHA (security/PII + code allowlist).
- Секреты лежат вне репозитория: `~/.config/studio-bot/secrets.env` (`chmod 600`). Загружаются только через `app.settings.load_settings()`.
- Права приложения YCLIENTS — только просмотр (T-001).

## Запуск (владелец, вручную)

```sh
# Fail-closed по умолчанию: без флага секреты не читаются и запросов нет.
make spike

# Авторизованный запуск (интерактивно запросит подтверждение фразой):
make spike SPIKE_ARGS=--authorize-live-read

# С приватной проверкой поиска по телефону (телефон спросит getpass, не из CLI,
# не из истории shell; в вывод и fixtures не попадает):
make spike SPIKE_ARGS="--authorize-live-read --probe-phone"
```

## После запуска

1. Проверить вывод: категории статусов, отсутствие PII (их там и не должно быть).
2. Передать вывод и `tests/fixtures/yclients/*.json` независимому ревьюеру для сверки схемы.
3. Только после PASS: вручную выставить `status: verified` и `path` для подтверждённых операций в `API_MATRIX.yaml`, заполнить `yclients_staff_id` / `yclients_resource_ids` залов в `studio.yaml`. Для не подтверждённых — оставить `pending` или `unavailable` с fallback.
4. `unavailable` фиксировать с обоснованием; тихая подмена полей запрещена.

Пока реальный spike не выполнен и не проверен, живой поиск YCLIENTS остаётся отключённым, T-104 начинается только после этого.

## 1. Зачем бот

1. **Ставить задачи администраторам** — из обращений клиентов и преподавателей и по правилам.
2. **Протестировать работу с клиентами и преподавателями через Telegram** — привязка, напоминания, ответы, отзывы, запросы на аренду.
3. **Делать рассылки** клиентам и преподавателям в Telegram.
4. **Загрузить пустующие окна аренды** — найти стабильно пустые слоты и предложить их преподавателям.

Всё остальное (клиентская база, платежи, абонементы, отчёт по аренде, запись) остаётся в YCLIENTS и делается как сейчас. Бот хранит только Telegram-данные и связку с карточкой YCLIENTS.

## 2. Студия (сайт yoga-rostov-mst.ru и кабинет YCLIENTS)

- «Центр практик „Мастерская“», Ростов-на-Дону. Работает ежедневно 07:00–22:00.
- Три зала: **Большой** (70 м²), **Малый** (30 м²), **Чайная** (45 м², проходная).
- Цена аренды фиксированная и зависит от времени: будни до 18:00 и будни после 18:00 / выходные. Значения — в studio.yaml.
- На сайте шесть направлений групповых практик с разными преподавателями.
- **Аренду бронирует администратор.** Отчёт по аренде ведётся в YCLIENTS.

## 3. Как это устроено в YCLIENTS (скриншот журнала)

| Объект в журнале | Что это | Как читать |
|---|---|---|
| Колонка-сотрудник «Преподаватель йоги» | Штатный преподаватель | Его групповые события (`6/15`, `1/15` — записано/вместимость), повторяющиеся, с ресурсом «Большой зал #1» |
| Колонки «Малый зал», «Большой зал», «Чайная» с должностью «аренда» | Залы, заведённые как сотрудники | Записи на них — аренда |
| Запись «Аренда малого зала 1 час» на колонке зала | Бронь аренды | **Клиент записи = арендатор-преподаватель**; в комментарии — название и цена его мероприятия |
| Ресурс «Большой зал #1» | Зал как ресурс | Связывает групповое занятие с залом |

Следствия:
- **Арендатор в YCLIENTS — клиент**, а не сотрудник. Его ученики в YCLIENTS обычно не заведены.
- **Занятость зала** = записи на колонке зала + групповые события с ресурсом этого зала.
- **Клиенты студии** записываются на групповые события штатных преподавателей.

## 4. Пользователи бота

| Роль | Кто | Как определяется |
|---|---|---|
| Клиент | Посетитель групповых занятий | Телефон из Telegram совпал с одним клиентом YCLIENTS |
| Преподаватель | Штатный (сотрудник YCLIENTS) или арендатор (клиент с арендой) | Приглашение от администратора + телефон |
| Администратор | Сотрудник студии; владелец — администратор с флагом `owner` | Приглашение; первый владелец — из настроек |

## 5. Состояние интеграции

- Непубличное приложение YCLIENTS `52175` (`studio_telegram_automation`), доступ к API есть.
- ID филиала (`company_id`) — **616370**. Токен партнёра получен; решения по токенам — в журнале DECISIONS. Значения токенов нигде в документах не воспроизводятся.
- В приложении были отмечены все права — сокращаются до просмотра (T-001).
- Обязательное поле webhook URL заполняется адресом, который никуда не ведёт: бот webhook не использует (ADR-04).
- Пути API — кандидаты в API_MATRIX; рабочие фиксирует `make spike` (T-103).
- Ни одна функция бота ещё не реализована.

## 6. Термины для кода

`company` — филиал · `hall` — зал (сотрудник-колонка + ресурс) · `activity` — групповое событие · `record` — запись (клиента на занятие или арендатора на зал) · `rent_record` — запись, чья услуга начинается с «Аренда» · `slot` — час зала · `empty_window` — подряд идущие стабильно пустые слоты · `rsvp` — «Приду / Не смогу», только информация · `task` — задача администратора · `domain_event` — изменение, вычисленное из снимков.

**Не смешивать:** RSVP ≠ статус записи ≠ явка. Отсутствие ответа ≠ отмена. Бот ничего не пишет в YCLIENTS.
